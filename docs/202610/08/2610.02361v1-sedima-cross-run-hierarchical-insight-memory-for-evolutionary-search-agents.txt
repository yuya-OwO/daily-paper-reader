## SEDIMA : Cross-Run Hierarchical Insight Memory for Evolutionary Search Agents 

Amirhossein Abaskohi 1*, Mahdi Mostajabdaveh 2, Zirui Zhou 21University of British Columbia, 2Huawei Technologies Canada 

Abstract 

Large language model (LLM)-driven evolution-ary search is a powerful paradigm for auto-mated program and algorithm discovery, yet existing systems are largely memoryless : each run explores from scratch, so agents repeat-edly rediscover the same improvements and re-encounter the same dead ends. We intro-duce S EDIMA , a persistent hierarchical insight memory for evolutionary search agents. S ED - 

> IMA

distills raw traces into natural-language in-sights, clusters them by semantic similarity us-ing attention-weighted centroids, and retrieves relevant guidance to condition future mutations, accumulating transferable knowledge across 

runs and problems rather than within a single trajectory. As a drop-in module that leaves the search operators unmodified, S EDIMA im-proves average final performance by 5.5% on AlgoTune and 6.6% on ALE-Bench LITE 

under a fixed budget of 100 evaluated candi-dates. Under OpenEvolve, S EDIMA reaches baseline-best performance with 32.3% fewer iterations on average across the five evaluated backbones 1.

1 Introduction 

Recent advances have turned LLMs from one-shot code generators into iterative search oper-ators. Rather than producing a single solution, these systems repeatedly select promising candi-dates, use an LLM to propose semantically in-formed modifications, evaluate the resulting pro-grams, and retain the strongest variants for further refinement (Romera-Paredes et al., 2023; Novikov et al., 2025). This formulation has enabled progress in mathematical discovery, algorithm design, and heuristic synthesis, while open-source frameworks such as OpenEvolve, ShinkaEvolve, and LLM4AD

have made the approach increasingly accessible (Sharma, 2025; Lange et al., 2025; Liu et al., 2026). Despite this success, these systems are funda-mentally memoryless : each run begins from scratch and discards the reasoning that produced its suc-cesses and failures the moment the run terminates. This is wasteful in two ways. Across runs, an agent applied to a new task re-derives modifications it has already discovered and re-explores directions that were previously neutral or useless, because it retains no record of why a past edit helped or hurt. Within a single run, the search trajectory is unstable: solution quality fluctuates sharply across iterations as the agent proposes, forgets, and re-proposes locally useful edits, with no persistent signal consolidating what is working. Recent work begins to close this gap by conditioning mutation on reflective signals rather than raw code (Ye et al., 2024; Wan et al., 2025; Jiang et al., 2026), but in each case memory remains within a single evolu-tionary trajectory and resets when a new run begins. We introduce S EDIMA , a persistent hierar-chical insight memory for evolutionary search agents . S EDIMA distills raw evolution traces into compact natural-language insights capturing why an edit succeeded or failed, then organizes them into a three-level hierarchy : raw traces, distilled insights, and semantically clustered insights whose cluster representatives are formed by attention-weighted centroids , so that prototypical, high-value lessons dominate retrieval. To condition a mutation, S EDIMA retrieves relevant guidance by semantic similarity and injects it into the prompt. Two properties distinguish how this memory is used. First, it persists across runs and problems ,so each run is warm-started with distilled experi-ence rather than starting cold. 2 Related Work 

Prior work has begun to give evolutionary search agents a memory, but it stays confined to a single run or requires rearchitecting the search. ReEvo (Ye et al., 2024) reflects over performance differ-ences, LoongFlow (Wan et al., 2025) summarizes each generation into insights retrieved along the genealogical lineage, and DeltaEvolve (Jiang et al., 2026) stores pairwise semantic deltas; in all three, memory is scoped to one trajectory and discarded when the run ends, whereas S EDIMA persists in-sight across runs and problems and retrieves it by semantic similarity rather than lineage. CORAL (Qu et al., 2026) and PRISM (Mishra, 2026) add persistent memory but only by turning the loop into long-running multi-agent systems, whereas S ED -

IMA is a single-agent, drop-in module that leaves the search operators unmodified. Beyond evolu-tionary search, general-purpose agents accumulate reusable knowledge across episodes as distilled insights (Zhao et al., 2024; Ouyang et al., 2026), skills (Wang et al., 2024), or verified experience li-braries (Kong et al., 2025), and others meta-evolve the memory architecture (Zhang et al., 2026) or train a memory policy with dense rewards (Li et al., 2026); S EDIMA instead brings this distill-embed-retrieve recipe to population-based evolution with a non-parametric, hierarchically clustered store whose attention-weighted centroids (Gonçalves et al., 2023) let high-value insights dominate re-trieval. To our knowledge, S EDIMA is the first hierarchical memory for single-agent evolutionary search that transfers across runs and problems with-out changing search operators. 

3 SEDIMA 

Figure 1 shows how S EDIMA connects to evolu-tionary search through two hooks: a write after each evaluation and a read before each mutation. It leaves the search logic unchanged while maintain-ing a persistent three-level memory hierarchy that carries experience across runs and problems. 

Level 1: raw traces. After each evaluation, S ED -

IMA stores a trace containing the step index, parent and child fitness, fitness difference, event source, and raw evaluation report. Level 1 performs no in-terpretation and serves as evidence for higher-level memories. Retaining these traces allows retrieved recommendations to remain linked to the evalua-tion events from which they were derived. Level 2: distilled insights. An LLM converts each trace into a compact natural-language insight and links it back to its Level 1 evidence. For the initial evaluation of a problem, it generates a problem-level insight describing the main algorithmic or ar-chitectural bottleneck. For each subsequent parent– child evaluation, it generates a change-level insight describing the type of modification and its observed performance effect using the parent fitness, child fit-ness, fitness delta, change summary, and evaluation report. These abstractions remove implementation-specific details while preserving reusable lessons such as beneficial caching, pruning, vectorization, data-structure changes, or reductions in redundant computation. Each insight is embedded for seman-tic organization and retrieval. 

Level 3: semantic clusters. Level 2 insights are grouped by embedding similarity: a new in-sight joins the nearest cluster if its cosine simi-larity exceeds a threshold and otherwise starts a new one. Cluster representatives are refreshed as members are added, and an optional LLM sum-mary captures the recurring optimization pattern. Rather than a plain mean, S EDIMA uses a non-parametric attention-weighted centroid that assigns larger weights to semantically central, prototypical insights; lower temperatures sharpen this emphasis, while higher temperatures approach mean pooling. Appendix A provides the formal definitions. 

Hierarchical retrieval. Before mutation, S EDIMA 

embeds a query describing the current program and its observed issues, retrieves the Kc most similar clusters above a threshold, and then selects the Ki

most relevant insights from each. Retrieved items retain cluster- and insight-level similarity scores and may include up to two linked Level 1 traces. An LLM converts this evidence into 3 concrete rec-ommendations inserted into the diff or full-rewrite prompt without changing the harness logic. Be-cause retrieval is semantic rather than genealogical, lessons can transfer across problems with similar failure modes or optimization patterns. 

Budgeting and fallback. Retrieval is bounded by fixed limits on clusters, insights, and prompt length, so context cost remains constant as memory grows. If no cluster passes the threshold, S ED - 

> IMA

falls back to the original mutation prompt. Each write adds one distillation call and one in-sight embedding, while each memory-conditioned mutation adds one query embedding and one recommendation-synthesis call; optional cluster summaries require only periodic write-time calls. Appendix A provides the full procedure. 

4 Experiments 

4.1 Experimental Setup Benchmarks and evaluation protocol. We eval-uate S EDIMA on AlgoTune (Press et al., 2025), reporting the harmonic mean speedup over nu-merical programming tasks, and the ten-problem ALE-Bench LITE subset (Imajuku et al., 2025), re-porting its problem-agnostic average performance score and separate short- and long-format results. Search uses only public local-evaluation scores as fitness, while all reported results come from private evaluation. We integrate S EDIMA into OpenEvolve (Sharma, 2025) and ShinkaEvolve (Lange et al., 2025) without changing their selection, popula-tion, evaluation, or mutation logic. Each run is limited to 100 evolution steps with one evaluated child per step. Comparisons are therefore matched by the number of evaluated candidates rather than total LLM calls or tokens; S EDIMA incurs addi-tional memory-construction and recommendation-synthesis calls as described in Section 3. Main-table cells use one run, while the per-step, ablation, and transfer experiments use three seeds. Memory is populated using disjoint problems, ensuring that no evaluation problem contributes to the memory used to solve it. 

Models and implementation. We evaluate GPT-5.4 (OpenAI, 2026), DeepSeek V4 Pro (DeepSeek-AI, 2026), Gemini 3 Pro (Google DeepMind, 2025), Qwen 3.7 Max (Qwen Team, 2026), and Qwen 3 Coder (Cao et al., 2026). All LLM calls within a run use the same backbone, preventing stronger models from being used for memory construc-tion or retrieval. We use a temperature of 0.7

for mutation and 0.2 for insight distillation, clus-ter summarization, and recommendation synthesis. Embeddings are produced by Qwen-Embedding-4B (Zhang et al., 2025) and fixed across conditions. We set the cluster threshold to τcluster = 0 .8, re-trieval threshold to τret = 0 .6, and centroid tem-perature to τ = 0 .1, and retrieve up to Kc = 3 

clusters with Ki = 3 insights per cluster. Retrieved evidence is limited to 2,500 tokens across all mod-els and harnesses. Each insight may include up to two linked traces, and the synthesizer returns three recommendations. Appendix B provides the full configuration. 5 Conclusion 

We introduced S EDIMA , a persistent hierarchical in-sight memory for evolutionary search agents. S ED - 

> IMA

distills raw traces into natural-language in-sights, organizes them using attention-weighted semantic clusters, and retrieves relevant guid-ance for future mutations. Through only two interfaces—a write after evaluation and a read be-fore mutation—the same module integrates un-changed with OpenEvolve and ShinkaEvolve with-out modifying their search operators. Across both harnesses, S EDIMA improves average final perfor-mance by 5.5% on AlgoTune and 6.6% on ALE-Bench LITE under a fixed budget of 100 evaluated candidates. Under OpenEvolve, it requires 32.3% fewer iterations on average to reach baseline-best performance across the five evaluated backbones. Because retrieval is semantic rather than genealog-ical, insights also transfer to problems and bench-mark families from which they were not derived. The current store grows without bound, motivating consolidation and forgetting mechanisms at larger scales. 

Limitations 

SEDIMA depends on LLM-generated insights and embedding-based retrieval, so inaccurate sum-maries, weak semantic matches, or noisy evalu-ation reports may store and reuse misleading guid-ance. Its effectiveness also depends on fixed cluster-ing and retrieval hyperparameters, and the current memory grows without consolidation or forgetting, which may reduce efficiency and relevance at larger scales. Our comparisons match methods by the number of evaluated candidates rather than total LLM calls, tokens, wall-clock time, or monetary cost; because S EDIMA adds distillation, embed-ding, and recommendation-synthesis operations, reductions in evolution steps should not be inter-preted as equivalent reductions in total compute. The main results use one run per model–harness pair because of the cost of full 100-step evolution-ary trajectories, while the per-step, ablation, and transfer analyses use three seeds. Finally, we do not directly benchmark against alternative memory-based evolutionary systems, so our experiments establish the benefit of adding S EDIMA to matched memoryless harnesses rather than superiority over all existing memory mechanisms. 

Ethical Considerations 

SEDIMA inherits the biases, hallucinations, and unsupported reasoning of its underlying language models, and persistent memory may amplify an incorrect insight across later mutations or runs. The additional distillation, retrieval, and synthesis calls also increase computational and environmen-tal cost, although retrieval is bounded by a fixed token budget. Our experiments use public bench-marks, models, and implementations under their respective licenses and involve no human subjects or newly collected personal data. We used LLM assistance only to improve manuscript presentation, with all technical decisions, experiments, and con-clusions verified by the authors; released code and artifacts will document dependencies and will re-distribute third-party data or model outputs only when permitted by their licenses.

B Experimental Setup Details 

Benchmarks. AlgoTune consists of numerical programming tasks in which a generated solver must reproduce a reference implementation while reducing execution time. We report the harmonic mean of per-task speedups. ALE-Bench contains AtCoder Heuristic Contest problems with contin-uous, non-saturating objectives. We use the ten-problem LITE subset and report average perfor-mance, a problem-agnostic score derived from the human leaderboard. Following Imajuku et al. (2025), we avoid rating because it can be dominated by a single exceptional result, and additionally re-port the five short- and five long-format problems separately. 

Evaluation protocol. During evolution, candi-date fitness is computed only from the public local cases supplied by each benchmark. Final results are obtained through private evaluation, and pri-vate scores are never exposed to the search proce-dure. Because our 100-step ALE-Bench budget is smaller than that used in published leaderboard submissions, absolute scores should be interpreted only through matched comparisons within our ex-periments. 

Harnesses and search budget. We attach S ED - 

> IMA

to OpenEvolve and ShinkaEvolve through the evaluation-write and mutation-read hooks. Their original selection, island-based population manage-ment, evaluation, and mutation procedures remain unchanged. Each run contains at most 100 evolu-tion steps, with one child generated and evaluated per step. The main tables report one run per model– harness pair because of the cost of full evolution-ary trajectories. The per-step, component-ablation, embedding-ablation, and memory-transfer exper-iments are each averaged over three independent seeds.

D.4 Interpretation 

This example demonstrates the full S EDIMA write– retrieve–apply cycle. The evaluator first identi-fies that the 2.36 × candidate remains solver-bound. SEDIMA stores the raw evidence, distills it into a solver-selection insight, and clusters it with struc-turally similar experiences. During a later mutation, the current program retrieves this insight and uses it to reformulate the model with CP-SAT, producing the 3.99 × candidate. The 3.99 × implementation also introduces a 30 -second solver limit and accepts both OPTIMAL and 

FEASIBLE CP-SAT solutions, whereas the CBC im-plementation returns a solution only after proving optimality. The observed gain may therefore re-flect both a more suitable solver formulation and a different termination policy. A controlled evalua-tion should additionally compare objective values and report how often CP-SAT terminates with an optimal rather than merely feasible solution.
